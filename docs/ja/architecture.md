# 設計

refrain の今の組み立てと、守っている規則を書きます。機能が増えるのに合わせて書き足します。

## スレッドとそれぞれの規則

```
MIDI スレッド ──(lock-free キュー)──┐
                                    ▼
メインスレッド                    オーディオスレッド
  プラグインの読み込みと有効化        キューからノートを読む
  プラグインからの呼び出しに答える    エンジンとプラグインの process() を動かす
  確保・ロック・待ちをしてよい        確保・ロック・待ち・I/O をしてはいけない
```

オーディオスレッドには締め切りがあります。48 kHz・128 フレームのブロックなら、毎回約 2.7 ms で
終えなければなりません。間に合わないと、プツッという音になって聞こえます。そのため、
オーディオスレッドで動くコードは次のことをしません。

- メモリの確保と解放
- 他のスレッドが持つかもしれないロックを取ること
- I/O、print、待ち

オーディオスレッドが使うものは、すべてストリームを始める前に確保します。ブロックのバッファ、
1 ブロック分のイベントの一覧、プラグインのチャンネルごとのバッファです。

## crate

### `refrain-engine`

エンジンです。OS、デバイス、ファイルのコードを持たず、依存もありません。

- `Processor` は、インターリーブされた `f32` のバッファを埋めるものです。
  `prepare(sample_rate, max_block_frames)` を呼んだあと、`process(out, channels, events)` を
  繰り返し呼びます。呼ばれたとき、`out` にはその処理への入力が入っています。列の中で前の処理が
  出した音か、無音です。インストゥルメントはそれを置き換え、エフェクトはそれを変えます。
- ブロックは最大 `MAX_BLOCK_FRAMES`（1024）フレーム、イベントは最大 `MAX_BLOCK_EVENTS`（256）個です。
  そのため、バッファの大きさを先に決められます。
- `Event` は演奏者の操作です。ノートオンとノートオフ、サステインペダルなどのコントローラー、
  ピッチベンド、アフタータッチがあります。値は MIDI 1.0 の範囲のまま持つので、どのイベントも
  失うものなく MIDI としてプラグインに渡せます。`TimedEvent` は、それをブロックの中のフレーム
  位置に置きます。
- `SustainPedal` は、ノートしか分からないインストゥルメントの代わりにペダルを弾きます。
  ペダルを踏んでいる間はノートオフを止めておき、離したときにまとめて送ります。ペダルで保持して
  いる鍵盤をもう一度弾くと先にそれを止め、All Notes Off はそのチャンネルの音をすべて止めます。
- `render_offline` は、デバイスを使わずに `Processor` を動かします。デバイスと同じように、
  指定した大きさのブロックに分けて呼び、各ブロックにはその範囲に入るイベントを渡します。
- `render_until_quiet` は同じことをしたあと、音が消えるまで続けます。`Tail` で決めた数の
  フレームが続けてしきい値以下になるか、いちばん長い余韻に届くまでです。最後の無音のフレームは
  切り落としますが、指定したフレームより短くはしません。どこで終わるかも、ブロックの大きさに
  よりません。

### トラックとミックス

`Track` は、処理の列（インストゥルメントと、その後ろのエフェクト）と、`Mix`（dB での音量、
パン、ミュート、ソロ）の組です。`Mixer` は `Processor` で、トラックをそれぞれ専用のバッファに
鳴らして足し合わせ、その合計をマスターのエフェクトの列とマスターの音量に通します。

- 列の中の処理は、それぞれ前の処理が埋めたバッファを受け取ります。順番はプロジェクトに書いた
  順で、テスト用エフェクトを使うと、順番の違いが音に出ます。
- ライブのイベントは 1 つのトラック（ライブのトラック）の、インストゥルメントにだけ届きます。
  エフェクトにはイベントを渡しません。
- パンは片側を下げ、もう片側はそのままにします。真ん中ではトラックはちょうど自分の音量なので、
  ミックスが既定のままのトラックは、ビット単位でそのまま通ります。パンがあるのはステレオだけで、
  それ以外のチャンネル数では音量だけを掛けます。
- どれかのトラックがソロのときは、ソロのトラックだけが聞こえます。ミュートはソロより強いです。
  ミュートしたトラックも鳴らし続けるので、インストゥルメントとクリップは時間どおりに進み、
  戻したときに正しい位置から聞こえます。
- トラックのバッファは `prepare` で、最大 `MAX_CHANNELS`（32）チャンネル分を確保します。
  それより多いと、オーディオスレッドで確保する代わりに無音を出します。

ミキサーはトランスポートでもあります。各トラックは自分の並び（タイムラインのフレーム位置に置いた
イベント）を持ち、ミキサーは再生中にそれを鳴らします。止まっている間は再生位置が動かず、ライブの
イベントとプラグイン自身の音は続きます。止めたとき、再生位置を移したとき、ライブのトラックを
変えたときは、すべてのインストゥルメントに、16 チャンネルすべてのペダルを離す指示と
All Notes Off を送り、鳴り残る音が出ないようにします。メトロノームもミキサーの一部で、
マスターの上に、再生中だけ鳴ります。`play`、`stop`、`locate`、`set_mix`、`set_master_volume`、
`set_click`、`set_live_track` は、どのブロックの間にも呼べて、どれもメモリを確保しません。

`deinterleave` は `interleave` の逆で、インターリーブされた信号を、プラグインの入力のチャンネル
ごとに分けます。モノラルの信号はすべての入力チャンネルへ、モノラルのプラグインには混ぜて 1 つにし、
信号に無い入力チャンネルは無音にします。

### タイムライン

クリップのイベントは tick（1 拍 = 960 tick）で持ちます。テンポを変えても、音楽としての位置が
保たれるようにするためです。エンジンのタイムラインのモジュールには、次のものがあります。

- `Tempo`: tick を秒やフレームに、またその逆に変換する
- `Sequencer`: 別の `Processor` を包む `Processor`。イベントの並びを、先頭からの正確なフレームで
  鳴らし、ライブで渡されたイベントと混ぜる。メトロノームも足せる。エンジンの他の部分と同じく、
  ブロックの大きさによらず同じサンプルを出す
- `Recording`: イベントを、届いた秒と一緒に集める。終えるときに、押さえたままの音を離し、
  踏んだままのペダルを上げる。そのため、再生したクリップが音を鳴らしっぱなしにすることはない

`refrain record` は、プロジェクトのクリップをインストゥルメントで鳴らしながら、MIDI から入ったものを
新しいクリップとして録音します。MIDI スレッドが、オーディオスレッドに渡す前に、各イベントに届いた
瞬間を記録します。そのため、録音の正確さはブロックの大きさではなく、MIDI のタイムスタンプで決まります。
録った秒は、プロジェクトのテンポで tick に変えます。メトロノームの音は出力に混ぜるだけで、録音には
入りません。

### `refrain-clap`

[`clack-host`](https://github.com/prokopyl/clack) を使って CLAP プラグインをホストします。

- `ClapPlugin` はメインスレッドに置きます。プラグインのインスタンスを作り、サンプルレートと
  ブロックの大きさを決めて有効にします。プラグインから求められたら、メインスレッドでの
  呼び出しにも答えます。
- 有効にすると `ClapProcessor` が返ります。これは `Processor` で、オーディオスレッドに渡します。
  CLAP の決まりどおり、最初のブロックでオーディオスレッドの上で処理を始めます。
  イベントは、プラグインのノートポートが分かる形式で渡します。MIDI を受け取るプラグインには、
  ノートは（CLAP のノートも受け取れるなら）CLAP のノートとして、それ以外は MIDI として渡します。
  ペダルはプラグインが自分で処理します。CLAP のノートしか受け取らないプラグインにはノートだけを
  渡し、ペダルは `SustainPedal` が代わりに弾きます。エフェクトには、列の中でその前にある音を
  メインの音声入力に渡します。それ以外の入力（サイドチェーンなど）は無音です。プラグインの
  メイン出力はインターリーブして返します。モノラルの
  プラグインはすべてのチャンネルへ、ステレオのプラグインをモノラルのデバイスに出すときは
  混ぜて 1 つに、デバイスのほうがチャンネルが多いときは残りを無音にします。
- `ClapPlugin` を破棄する前に、オーディオのストリームを止めなければなりません。その時点で
  まだ処理側が生きていると、clack はオーディオスレッドの下で壊さないよう、インスタンスを
  破棄せずにメモリを漏らします。
- `ClapProcessor` を破棄すると、処理を止めます。CLAP は、プラグインを無効にする前にそうするよう
  求めています。次の `activate` は、先にプラグインを無効にします。そのため、最後の処理側が
  なくなっていれば、ブロックの大きさを変えたり、トラックが変わったりしたあとに、プラグインを
  有効にし直せます。最後の処理側がまだ生きていると、`activate` は断ります。

### `refrain-vst3`

[`vst3`](https://github.com/coupler-rs/vst3-rs) のバインディングを使って VST3 プラグインを
ホストします。

- `Vst3Module` は読み込んだ `.vst3` のバンドル（macOS）またはファイル（Windows）です。macOS では、
  プラグインが期待するとおり、`bundleEntry` に本物の `CFBundleRef` を渡します。
- `Vst3Plugin` はメインスレッドに置きます。コンポーネントとコントローラーを作り、
  コネクションポイントでつなぎ、コンポーネントの状態をコントローラーに渡して、メインのバスを
  有効にします。
- 有効にすると `Vst3Processor` が返ります。オーディオスレッド用の `Processor` で、最初のブロックで
  オーディオスレッドの上から `setProcessing` を呼びます。エフェクトには、列の中でその前にある音を
  最初の音声入力に渡します。それ以外の入力は無音です。
- VST3 には MIDI のコントローラーのイベントがありません。有効にするとき、ホストはプラグインの
  `IMidiMapping` を、すべてのチャンネルとコントローラー（ピッチベンドとチャンネルアフタータッチを
  含む）について読みます。対応付けのあるコントローラーは、そのサンプル位置でのパラメータの変化と
  して送ります。それ以外は、ノートしか受け取らない CLAP のプラグインと同じく `SustainPedal` を
  通します。
- `process` に渡すイベントの一覧とパラメータの変化は、refrain が実装した COM のオブジェクトです。
  有効にするときに確保し、使い回します。
- CLAP と同じく、`Vst3Plugin` を破棄する前にストリームを止めなければなりません。止めずに破棄すると、
  オーディオスレッドの下で壊さないよう、プラグインを破棄せずにメモリを漏らします。
- `Vst3Processor` を破棄すると `setProcessing(0)` を呼び、次の `activate` は先に `setActive(0)` を
  呼びます。そのため VST3 のプラグインも、最後の処理側がなくなっていれば有効にし直せます。

### プラグインの画面

`refrain play` と `refrain editor` は、[`winit`](https://github.com/rust-windowing/winit) で
作ったウィンドウに、メインスレッドでプラグインの画面を開きます。プラグインは、ウィンドウの
`NSView`（macOS）か `HWND`（Windows）に自分の画面を埋め込みます。CLAP は `gui` 拡張、VST3 は
`IPlugView` を使います。画面の大きさは、どちらの形式も macOS では論理ピクセル（ポイント）、
Windows では物理ピクセルです。

- プラグインが大きさの変更を求めたとき（CLAP の `request_resize`、VST3 の
  `IPlugFrame::resizeView`）は、メインループの次の回でウィンドウの大きさを変え、実際の大きさを
  プラグインに伝えます。
- VST3 のプラグインは、自分の画面で変えたパラメータをコンポーネントハンドラーで知らせてきます。
  refrain はそれを lock-free キューで処理側へ渡し、次のブロックの頭から効かせます。CLAP の
  プラグインは自分で反映します。
- 開いたあと、ウィンドウに子ビュー（子ウィンドウ）ができたかを確かめて表示します。ウィンドウを
  受け取ったのに何も付けないプラグインだと、理由が分からないまま空のウィンドウが出てしまうためです。
- 画面は、それを入れたウィンドウより先に、またプラグインより先に閉じます。

### プロジェクトとプラグインの状態

プラグインの状態は、そのプラグインだけが分かるバイト列です。refrain はそれをメインスレッドで
保存・復元します。

- CLAP: `state` 拡張の `save` と `load`
- VST3: コンポーネントの `getState` と `setState`、およびコントローラーの同じもの。復元するときは、
  コントローラーにも `setComponentState` でコンポーネントの状態を渡し、パラメータを揃えます

`refrain-project` は、プロジェクトを小さな JSON のファイルとして書きます。版 3 では、トラック
（それぞれインストゥルメント、エフェクト、ミックス、クリップ）と、マスター（エフェクトと音量）を
持ちます。どのプラグインも、形式・パス・ID と、base64 にした状態で書きます。状態が空なら、
プラグインは単体で読み込んだときと同じ状態から始まります。版 1 と版 2 はインストゥルメント 1 つと
そのクリップを持っていたので、そのトラック 1 本のプロジェクトとして読みます。

プラグインのパスが相対パスなら、プロジェクトのフォルダからの相対パスです。別の場所に保存し直すときや、
別のプロジェクトからトラックを足すときは、相対パスをすべて、新しい場所から同じファイルに届くように
書き換えます。そのため、隣に置いたプラグインと一緒にプロジェクトを動かせます。書く前にプロジェクトを
検査するので、refrain は自分で読めないプロジェクトを書きません（たとえば無限大の音量は JSON で
表せません）。保存するときは一時ファイルに書いてから古いファイルに名前を付け替えるので、保存に
失敗しても古いプロジェクトは壊れません。

VST3 のクラス ID は、VST3 SDK が表示するのと同じ形で保存します。Windows はクラス ID を COM の
GUID としてメモリに並べ、最初の 8 バイトの順番が違います。生のバイト列をそのまま書くと Windows では
別の ID になり、Mac で保存したプロジェクトが Windows でプラグインを見つけられなくなります。

### テスト用プラグイン

`refrain-test-tone` は小さなサイン波のシンセです。`refrain-test-synth`（CLAP）と
`refrain-test-synth-vst3`（VST3）は、どちらもこれを鳴らします。第三者のバイナリを使わずに
ホスト機能をテストできるよう、このリポジトリで作っています。ノートはそれぞれその高さのサイン波で、5 ms のフェードイン・
フェードアウトが付きます。右チャンネルは左チャンネルの半分の大きさです。結果が決まっているので、
テストで正確な値を確かめられます。左右が違うので、チャンネルの取り違えや複製が見えます。

どちらの形式にも、同じ音のプラグインが 2 つあります。1 つはコントローラーを受け取り、
サステインペダル、ピッチベンド、All Notes Off を自分で処理します。CLAP 版は MIDI として、VST3 版は
`IMidiMapping` で対応付けたパラメータとして受け取ります。もう 1 つはノートしか受け取らないので、
ペダルは refrain が代わりに弾きます。テストでは 4 つすべてに同じイベントを送り、同じサンプルが出る
ことを求めます。これで、refrain のペダルの再現をプラグイン自身の処理と、CLAP のホストを VST3 の
ホストと、互いに突き合わせています。

ホストからオフラインでの書き出しだと伝えられると（CLAP 版は `render` 拡張で、VST3 版は
プロセスモードで）、テスト用プラグインはそれを覚えておくので、届いたことをテストで確かめられます。
VST3 版は、設定されたときと違うプロセスモードのブロックが来ると、処理を失敗させます。

テスト用プラグインは、MIDI のコントローラー 7 で変わる音量を状態として保存します。状態の形式は
2 つの形式で同じなので、一方のホストで保存した状態を、もう一方のホストで復元できます。これで、
両方のホストがバイト列をそのまま渡しているかを確かめています。

どちらの形式にも、エフェクトも 1 つあります。音をゲイン倍（はじめは 2）して ±0.25 で切り、
ゲインを状態として保存します。切るので、2 つ続けると順番を逆にしたときに結果が変わります。
そのため、列を違う順番で通すホストはテストで落ちます。エフェクトに無音を渡すホストや、
エフェクトを飛ばすホストも落ちます。テストでは、エフェクトの列をどちらの形式でも、両方を
混ぜても通し、同じサンプルが出ることを求めます。

テスト用のインストゥルメントにも `refrain-test-editor` の画面があります。プラグイン名を出す 400 × 300 の
パネルで、ホストのウィンドウの子として付きます。本当に子になったかを自分で確かめ、なっていなければ
失敗します。そのため、違うウィンドウを渡すホストは CI の画面の検査を通れません。

`scripts/build-test-plugins.sh` は、これらをインストールされた形に包みます。macOS ではバンドル、
Windows では単体のファイルです。CI と、手元で試すときに使います。

テストでは 2 通りに読み込みます。プロセスの中に読み込む方法と、CI で包んだファイルから読み込む
方法（本物のプラグインと同じ読み込み方）です。

### `refrain`

`refrain` コマンドです。OS に触れる部分はすべてここが持ちます。

- オーディオデバイス: `cpal` を使う（macOS は CoreAudio、Windows は WASAPI）
- MIDI 入力: `midir` を使い、`rtrb` のキューでオーディオスレッドへ渡す
- WAV ファイル: `hound` を使う

`refrain render` は、すべてのプラグインにオフラインでの書き出しだと伝え（CLAP は `render` 拡張、
VST3 は `kOffline` のプロセスモード）、プロジェクトのトラックを最後のイベントまで書き出します。
そのあと、音が 100 dB 下がった状態が 2 秒続くまで（最長 60 秒）書き続けます。ファイルは 32 bit の
浮動小数か、16 bit か 24 bit の整数です。整数では最も近い段に丸め、フルスケールで切ります。
ディザーを指定すると、1 段分の三角分布のノイズを、固定の種から加えます。そのため、同じプロジェクト
からは毎回同じファイルができます。

デバイスのコールバックは、デバイスのバッファを最大 `MAX_BLOCK_FRAMES` のブロックに分け、
エンジンの出力を `f32` のバッファに書いてから、デバイスのサンプル型に変換します。

`Session` は、プロジェクトと、そこに書かれたプラグインをすべて読み込んで状態を戻したものです。
演奏や書き出しのための `Mixer` を組み立て（各トラックには、そのクリップを並びとして渡します）、
保存するときはすべてのプラグインの状態をプロジェクトに
書き戻します。プラグインのファイルを 1 つだけ開いたときは、トラック 1 本のプロジェクトになります。
`new`、`show`、`track`、`fx`、`mix` は、音を出さずにプロジェクトのファイルを書き換えます。
プラグインを読み込むのは、その形式・ID・名前を知るためだけです。

### refrain のウィンドウ

`refrain gui` は、トランスポート、トラックごとの行（ミックスとプラグインのあるヘッダーと、
クリップを並べたレーン）、マスターのあるウィンドウを開きます。描くのは
[egui](https://github.com/emilk/egui) で、`wgpu` を通します。プラグインの画面のウィンドウと
同じ `winit` のイベントループで動き、プラグインの画面は、そのプラグインのボタンから開きます。

- **見せるものと、することを分けています。** `view::show` は `Model`（ウィンドウに見せるものを
  写しただけのもの）を描き、押されたものを `Action` として返します。自分では何も変えません。
  テストは `egui_kittest` で、画面もデバイスもプラグインも使わずに、ボタンを押して確かめます。
- **オーディオスレッドにはキューで届けます。** ミキサーは `Remote` の中で動き、`rtrb` のキューから
  来た指示（再生、停止、位置の移動、トラックのミックス、マスターの音量、メトロノーム、ライブの
  トラック）をブロックの前に当て、再生位置を atomic で知らせます。ミックスの変更は、再生中でも
  次のブロックから聞こえます。
- **クリップの編集は、すぐ聞こえます。** 録音、移動、複製、削除、ノートの編集をしたクリップは、
  そのトラックの新しい並びとして、指示のキューでオーディオスレッドに届きます。ミキサーは再生位置から
  それを使い、そのトラックの音を離します（古い並びにあったノートオフが、無くなっているかもしれない
  ため）。古い並びは別のキューで送り返し、オーディオスレッドの外で解放します。プラグインを有効に
  し直さないので、再生中でもできます。
- **トラックやテンポを変えると、ミキサーを組み立て直します。** ストリームを止め、すべての
  プラグインを有効にし直して、同じ再生位置から始めます。
- **ノート。** クリップは MIDI のメッセージで持ち、ピアノロールはノートで扱います。ノートオンは、
  同じ鍵盤とチャンネルの次のノートオフと組にし、離されないままのノートはクリップの終わりで終えます。
  コントローラーなどは、そのまま残します。ノートから戻すときは、同じ tick の中でノートオフ、
  その他のイベント、ノートオンの順に書くので、離した位置で同じ鍵盤を弾き直しても音が出ます。
  録音したクリップは、分けて戻しても元のままです。
- **Undo** は、クリップやノートを編集する前の、全トラックのクリップの写しを持ちます。トラックや
  エフェクトを足したり消したりすると、写しは捨てます。それをまたいで戻すには、もう無いプラグインが
  要るためです。
- **ドラッグ**は、続いている間の量を覚えておきます。egui は、離したフレームでは、どれだけ
  ドラッグされたかを返さないためです。最初の版では何も動かないことを、テストが捕まえました。
- **録音**は、再生位置から再生を始め、MIDI から入ったものを（MIDI スレッドで付けた時刻ごと）
  集めます。止めると、録音を始めた位置から始まるクリップにして、MIDI が届くトラックに置きます。
- **プラグインの追加と削除**は `Session` を通します。`Session` は、ミキサーの組み立て直しを挟んで、
  プロジェクトと読み込んだプラグインを揃えたまま変えます。選ぶ画面は、プラグインのファイルを
  読み込まずに、インストール先のフォルダとプロジェクトから並べます。ファイルを読み込むのは、
  選ばれて中のプラグインを並べるときだけです。削除するときは、後ろのプラグインの番号がずれるので、
  開いている画面を先に閉じます。
- **ウィンドウの操作の処理もテストしています。** プラグインの一覧の作り方と読み込み方を差し替え
  られるので、テストではプロセスの中のテスト用プラグインで、ウィンドウの状態を動かします。
  選ぶ、足す、消す、保存していない変更を捨てる前に 2 回押させる、を確かめます。
- **フォントは OS のもの**を使います。理由はライセンスの方針に書いたとおりです。探すフォントが
  どれも無いと、ウィンドウは開きません。

## 分かっている制限

- **ノートのタイミング。** MIDI スレッドから来たノートは、弾いた瞬間ではなく、次のブロックの頭で
  始まります。48 kHz・512 フレームのバッファなら、最大で約 11 ms ずれます。
- **ノートしか受け取らないプラグイン**には、ピッチベンド、アフタータッチ、ペダル以外の
  コントローラーは届きません。CLAP のノートエクスプレッションで一部は伝えられますが、
  refrain はまだ送っていません。
- **プラグインのログ**は、ログを出したスレッドでそのまま表示します。オーディオスレッドのことも
  あります。
- **画面は埋め込みだけ。** 画面を自分専用のウィンドウにしか出せない CLAP のプラグインには、
  まだ対応していません。Linux で一部のプラグインが再描画に使う CLAP のタイマー拡張も未対応です。
- **録音は、聞こえた音に揃えていません。** 時刻はオーディオのストリームが始まったときから、
  出力のレイテンシを引かずに測るので、録音は数ミリ秒遅れて入ります。カウントインはまだ無く、
  クリップはすべてタイムラインの先頭から始まり、テンポはプロジェクト全体で 1 つです。
- **エフェクトのレイテンシを補正していません。** レイテンシを報告するプラグインがあっても、
  ほかの音をその分遅らせることはまだしません。
- **書き出し**は WAV だけで、指定したサンプルレートのまま書きます。サンプルレートの変換、
  ノーマライズ、トラックごとの書き出し（ステム）はありません。リアルタイムでの処理が欠かせない
  プラグインも、オフラインで書き出します。
- **演奏中はトラックとエフェクトが固定です。** refrain のウィンドウでは演奏中もミックスを
  変えられますが、トラックやエフェクト、新しいクリップを足すにはプラグインを有効にし直す必要が
  あり、それは止まっている間に行います。センド、バス、グループ、オートメーションはまだ無く、
  エフェクトには MIDI もサイドチェーンも届きません。
- **refrain のウィンドウ**では、まだエフェクトの並べ替え、トラック名の変更、クリップの分割や
  長さの変更、ベロシティやコントローラーの編集ができません。タイムラインはいつも曲全体を収め、拡大や横のスクロールはできません。macOS では、
  `.clap` と `.vst3` のバンドルはフォルダなので、OS のファイル選択の画面では選べないことがあります。
  選ぶ画面の一覧と、パスの欄からは選べます。
- **プロジェクトを保存するのは、`--save` を付けて画面を閉じたときか `play` が終わったとき**です。
  演奏中の保存や自動保存はまだありません。
- **プラグインの場所が変わったプロジェクト**では、インストール済みのプラグインから ID で探すことは
  しません。探したパスを示して止まります。
- **倍率の違う画面の間でウィンドウを動かしても**、新しい倍率はまだプラグインに伝えません。
- **VST3 のメッセージ。** refrain はプラグインのために `IMessage` を作りません。コンポーネントと
  コントローラーはコネクションポイントで直接やり取りします。これまで試したプラグインでは、
  それで足りています。
- **一覧を作るとき、すべてのプラグインをこのプロセスで読み込みます。** 一覧の途中で落ちる
  プラグインがあると、refrain も一緒に落ちます。

## デバイスを使わない経路が大事な理由

CI のマシンにはサウンドカードがありません。そこで、エンジンとプラグインのホスト機能は
`render_offline` を通して検査します。この経路にもデバイスと同じ規則を課しています。

- **出力はブロックの大きさによらない。** 1、64、100、128、1000、1024 フレームのどのブロックで
  書き出しても、サンプルはビット単位で一致します。プラグインの有無や、ノートがブロックの途中で
  始まったり止まったりする場合も同じです。ブロックの大きさはデバイスが決めるので、それで
  変わるものはバグです。
- **テストは、捕まえるべきバグを捕まえる。** ホスト機能のテストは、ホストにわざとバグを入れて
  確かめました。イベントのフレーム位置を捨てる、違うチャンネルをインターリーブする、
  モノラルへの混ぜ合わせを飛ばす、MIDI のプラグインへのコントローラーを捨てる、ホストのペダルを
  飛ばす、保持している鍵盤を弾き直しても止めない、All Notes Off を無視する、ペダルの値 64 を
  離した扱いにする、の 8 つです。VST3 では、対応付けたコントローラーを送らない、ノートの
  サンプル位置を捨てる、パラメータの変化のサンプル位置を捨てる、ピッチベンドを 16384 で割る、
  MIDI の対応付けを読まない、画面での変更を捨てる、の 6 つです。状態については、CLAP の
  プラグインに空の状態を渡す、VST3 のコンポーネントの `setState` を飛ばす、VST3 の状態を空で
  保存する、の 3 つです。タイムラインについては、並びのイベントを 1 フレーム遅らせる、並びを
  鳴らしている間のライブのイベントを捨てる、終えた録音に押さえたままの音を残す、の 3 つです。
  エフェクトとミックスについては、エフェクトに入力の代わりに無音を渡す（両方のホストで）、列を
  逆順に通す、パンの左右を入れ替える、プロジェクトのミックスをミキサーに渡さない、の 4 つです。
  書き出しについては、VST3 のプラグインをオフラインで設定したのにブロックをリアルタイムで流す、
  オフラインを頼まれたのに CLAP のプラグインにリアルタイムと伝える、の 2 つです。トランスポートに
  ついては、止めてもインストゥルメントの音を離さない、止まっている間も再生位置を進める、再生位置を
  移しても並びの読み出し位置を移さない、の 3 つです。編集については、トラックの並びを差し替えても
  その音を離さない、同じ tick でノートオンをノートオフより先に書く、の 2 つです。
  どれもテストが落ちます。パンの入れ替えは、最初はエンジンのテストを通ってしまいました。テストの
  値が、左右を入れ替えても同じ合計になっていたためで、そうならない値に変えました。CI のミックスの
  検査は、チャンネルごとのピークから、パンの入れ替えとミックスの渡し忘れの両方を捕まえました。
  画面については、ホストがプラグインにウィンドウを渡すのを飛ばすようにしてみました。ウィンドウに
  子ができたかの確認がそれを捕まえました。うち 1 つは最初は通ってしまいました。
  テスト用シンセがホストの誤りを隠していたためで、隠さないようにシンセを変えました。

## OS ごとのコードは薄く保つ

macOS と Windows で違うものは、すべて外側に置きます。オーディオデバイス、MIDI ポート、
プラグインの画面のウィンドウハンドル（`NSView` と `HWND`）、プラグインを探す場所です。
エンジン、グラフ、トランスポート、プロジェクトファイル、プラグインのホスト機能の大部分は共通です。
